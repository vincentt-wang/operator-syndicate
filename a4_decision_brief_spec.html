2. 文件結構

2.1 封面頁（Page 1）

  • 主標題：寵物科技新創投資速覽（48pt, tealDark, Bold, 置中）
  • 副標題：Pet Tech Startup Investment Brief（24pt, teal, 置中）
  • 活動名稱 + AI-Assisted Decision Brief
  • 日期 + 作者名 + 職稱
  • 底部 Disclaimer 卡片（bg 底色，slateLight 文字，句號後分行）

2.2 閱讀指引頁（Page 2）

  • 標題：閱讀指引（36pt, tealDark, Bold）
  • 生態系定位說明（段落式，句號後分行）
  • 三類投資人視角：A / B / C 各一張獨立卡片，垂直排列
  • 每張卡片包含：名稱、定義（C 類需要）、投資階段、典型票額、適配信號、不適配信號
  • 分析框架說明：七層分析 + D/V/F 信號燈定義

三類投資人定義

A: 策略成長型基金 — Post-PMF 至 Scaling。NT$5,000 萬+ 或 US$1M+。

B: 早期驗證型創投 — Pre-Seed 至 Pre-A。NT$500-3,000 萬。股權或可轉換債。

C: 營運加速型聯盟 — 由資深產業決策層組成的聯合投資聯盟。核心價值不在資金，而在以產業經驗與企業決策層關係網絡加速 B2B 銷售週期。SPV 單案 NT$200-2,000 萬。

重要：C 類描述中不直接使用「高管人脈」一詞，改用「產業關係網絡」「產業經驗與企業決策層關係」「營運合作夥伴」等專業用語。

4. D/V/F 信號燈

符號標籤顏色用法
●通過teal該軸已被資料驗證
△待驗證amber有跡象但需進一步查核
✕紅旗red資料顯示明確風險

格式範例：● D: 通過 需求明確，500+ 醫院導入驗證

使用冒號（:）分隔軸名與判定，不使用斜號（/）或管線符（│）。

5. 內容撰寫規則

5.1 句號後分行

每個句號（。）後換行為新的 Paragraph，不擠在同一段。這是視覺呼吸空間的核心規則。

5.2 禁止括號解釋

不使用括號做解釋性文字，除非是專有名詞英文保留。例如：

  • ✕ 錯誤：「B2B2C（企業對企業對消費者）模式」
  • ● 正確：「B2B2C 模式」
  • ● 可接受：「液態切片 Liquid Biopsy」（英文專有名詞保留）

5.3 C 類投資人用語

  • ✕ 禁止：「高管人脈」「高管可以幫忙」
  • ● 使用：「產業關係網絡」「產業經驗與企業決策層關係」「營運合作夥伴」「產業關係可加速」

5.4 數據來源標註

所有來自 Pitch 的數據前加「簡報揭露：」，表示未經獨立查核。

5.5 填滿頁面

每家公司的分析應填滿整頁 A4，不留大面積空白。投資人分析表的七層內容是填充的關鍵。

8. 使用方式

  1. 新案源進來時：依照此規格建立新的公司資料物件（id, cn, tag, chain, biz, stage, url, date, cop, ep, d, v, f, rf, A, B, C, rt）
  2. 生成報告：使用 docx-js 按照此規格生成 .docx 檔案
  3. Claude Code 執行：讀取此規格檔 → 按照資料物件結構填入 → 輸出 .docx
  4. 更新規格：Vincent 確認新版本後，更新此檔案的版本號與內容

資料物件結構 (TypeScript-style)

interface CompanyData {
  id: string;       // 英文名
  cn: string;       // 中文名
  tag: string;      // 一句話定位
  chain: string;    // 價值鏈位置
  biz: string;      // 商業模式
  stage: string;    // 發展階段
  url: string;      // 官網
  date: string;     // 月份標註
  cop: string;      // Cost of Problem（句號分隔）
  ep: string;       // Elevator Pitch（句號分隔）
  d: [symbol, label, text];  // D 軸
  v: [symbol, label, text];  // V 軸
  f: [symbol, label, text];  // F 軸
  rf: string;       // Red Flag（句號分隔）
  A: InvestorView;  // 策略成長型
  B: InvestorView;  // 早期驗證型
  C: InvestorView;  // 營運加速型
  rt: string;       // 建議路由
}

interface InvestorView {
  fit: 0 | 1 | 2;   // 0=不適配, 1=條件式, 2=適配
  rs: string;        // 判斷理由
  dr: string;        // 建議切入方向
  $: string;         // 資金需求與結構
  pq: string;        // 推進前提
  rk: string;        // 最高風險假設
  lv: string;        // 最高槓桿
}
